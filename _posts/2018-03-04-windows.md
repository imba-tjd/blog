## 路径

* `D:123.txt`D盘的最后一次工作路径下的相对路径，如果没有则为根
* `\123.txt`表示当前盘根目录下的123.txt，属于绝对路径
* `\\PCName\123.txt`是UNC路径，表示局域网上的文件，其中PCName是计算机名，也可以是ip，123.txt是共享的文件名；用C$来表示共享的根目录
* `\\?\C:\123.txt`、​`\\?\UNC\PCName\123.txt`、`\\.\xxx`：设备路径，后面跟的是设备名；支持非常长的路径和单纯以点结尾的文件；不能用斜杠，只能是绝对路径
* `C:\directory\..\directory\file.txt`：.net算完全限定路径，但是带有相对路径符号，实际程序可能认为是无效路径​
* `a.txt`与`a.txt...`等视为同一文件

## 创建服务

* 正常的服务不能创建新的程序，只能创建别的服务。也许你需要的是计划任务
  * 创建托盘管理的程序：https://github.com/rexdf/CommandTrayHost/blob/master/README.zh-cn.md
* sc create 服务名 binPath= "路径"
  * start= demand默认手动 auto不登录就运行 delayed-auto延迟自动启动的会在其它自动启动的服务之后启动
  * DisplayName= XXX
  * 等号后必须有空格，必要时有引号
  * 只能用于本来就是服务（实现了ServiceMain），实测无法直接运行bat
  * 一般操作需要管理员权限，query不需要
  * 还有net start和stop也可以启停服务，但更老，只能操作本地，而sc可以操作网络上的。sc是异步的，start后不等程序相应直接返回了，net是同步的。二者都不存在restart命令
  * PowerShell的sc是另一个命令的alias，且输入参数后没有任何报错提示。可以用start-service
  * 管理服务：sc query xxx 显示是否正在运行。sc qc xxx 显示是自动还是手动启动。设为自动启动：sc config xxx start= auto
* NSSM:https://www.nssm.cc/ 有GUI但是好像不能脱离它运行；上次更新是2017年
* https://github.com/winsw/winsw C#写的，活着
* https://github.com/rozanski/srvstart 很老的程序，最初是给NT4写的
* https://github.com/NewLifeX/NewLife.Agent 跨平台支持Linux下注册为Systemd服务

## 计划任务(taskschd.msc)

* 如果是执行bat，有的说必需指定`Start in (optional)`，或者用cmd /c start "" ...。还有人说Start字段一定不能有引号，Start in也不可以，`program > program/script`可以有；反正依赖工作路径的一定要指定`Start in`否则会失败
* 如果是登录时执行的，好像必须要delay，否则很可能失败。而且实际上未输密码时的某个时候就已经开始计时了
* 图形界面可以右键运行，当时就能测试一下
* 隐藏运行：必须选`不管用户是否登录都要运行`，再勾上隐藏
* 关闭断开电源时默认会杀掉程序
* 一些图形界面可能出错的原因：https://serverfault.com/questions/734035/running-a-batch-file-from-task-scheduler-without-user-being-logged-in
* 实际会放到`C:\Windows\System32\Tasks`中，以xml的形式存在
* 日志默认关闭，开启用`REG ADD "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\WINEVT\Channels\Microsoft-Windows-TaskScheduler/Operational" /v Enabled /t REG_DWORD /d 1 /f`

### [Schtasks命令](https://docs.microsoft.com/zh-cn/windows/win32/taskschd/schtasks)

* at命令废弃了
* schtasks /Create /TN "计划任务名称" /TR "命令 参数"
  * /SC 频率，一般用ONSTART ONLOGON，再配合/DELAY 秒数。还可用HOURLY DAILY等，再配合/MO /ST等
  * /RL HIGHEST已最高权限运行
  * /RU 要执行命令的用户
  * 如果希望弹出界面，必须用/IT，只在登录后有效
  * 任务已存在时覆盖创建：/F
* schtasks /Run /TN "计划任务名称"
* 默认CWD为System32

```xml
<application xmlns="urn:schemas-microsoft-com:asm.v3">
    <windowsSettings xmlns:ws2="http://schemas.microsoft.com/SMI/2016/WindowsSettings">
        <ws2:longPathAware>true</ws2:longPathAware>
    </windowsSettings>
</application>
```

## bcdedit

* BCD文件位置：\EFI\Microsoft\Boot\BCD
* 注意使用PS时大括号外要加引号
* 无参运行相当于/enum ACTIVE，只会显示bootmgr及其displayorder中的项。指定FIRMWARE可看到固件顺序，指定
* bcdedit /sysstore C: 临时指定存放BCD文件的盘
* bcdedit /set recoveryenabled No 默认会使用`{current}`。nx AlwaysOff禁用DEP，Optin为系统组件启用
* 调整启动顺序，无需指定`{bootmgr}`：bcdedit /displayorder {1} {2}，可指定/addfirst,/addlast,/remove，都不指定就是覆盖；bootsequence只指定下一次的
* https://docs.microsoft.com/zh-cn/windows-hardware/drivers/devtest/bcd-boot-options-reference
* EFI分区的类型必须要是EFI（DG中可调），具有特殊的GUID，而不能仅仅只看文件类型

## Hosts

* 要用UTF8 with BOM，否则行尾注释有中文的时候有几率导致那一行失效

### NTFS

* fsutil 8dot3name
  * set 1：所有驱动器上禁止新建8.3文件记录，3为除系统盘以外禁止。好像refs默认没有
  * strip /s dir：递归去除dir的8.3文件记录，需管理员权限。对于系统目录一般会失败，可以给appdata用。会花时间扫描注册表里是否用到了，如果没用才会执行去除；另一种发现数>除去数的情形：文件正在运行，无法访问
* fsutil fsinfo sectorinfo c:：是否4KB对齐
* fsutil volume：dismount卸载卷，list列出所有卷
* fsutil behavior set memoryusage 2：增大NTFS元数据缓冲级别。disablelastaccess 1 不更新最后访问时间，Server默认启用
* fsutil fsinfo drives：列出磁盘
* fsutil file SetCaseSensitiveInfo 文件夹名称 enable：启用大小写区分

## 32位程序

* 分辨程序是32位的还是64位的：右键-属性-兼容性，如果下拉列表里有Win95，则是32位的
* 32位程序能使用的用户态内存：默认2GB
* 如果启用IMAGE_FILE_LARGE_ADDRESS_AWARE，且32位系统启用4GT，则32位系统上的32位程序可使用3GB用户态内存，64位系统上的32位程序可使用4GB（但仍无法连续分配超过2GB，因为系统DLL的地址在2GB边界处）
  * msvc: /LARGEADDRESSAWARE; mingw: --large-address-aware
  * 4GT：4-gigabyte tuning。xp的选项叫/3GB，win7后用BCDEdit /set increaseuserva MB数。仅对32位系统有意义
* 启用4GT前，内存地址小于0x80000000的就是用户地址；启用后，高于它的也可能是
* PAE物理地址扩展：可以认为已经默认启用（能启用DEP=>已启用PAE），操作系统能使用超过4GB的物理内存
* AWE地址窗口化扩展：允许程序使用超过4GB的物理内存，原理是动态映射一部分非分页物理内存到进程的虚拟地址空间。需编程使用WinAPI，不考虑

## RAID

* 原始RAID
  * RAID0 Stripping条带：一份数据分块均匀分别写入不同磁盘
  * RAID1 Mirroring：空间利用率为50%（或多盘时更低，可用容量等于1块）
  * RAID5 Parity：至少需要3块硬盘（可以更多），以其中一块的容量，交错分布校验信息，最多允许损坏任意一块，写入慢。如果硬盘是同一时期买的，可能一块坏时其它的也快坏了。另一种说法：硬盘有个很低的数据损坏率，但当阵列中一块硬盘挂掉，更换一块重建阵列时，会读取所有硬盘的所有数据，大概率一定有错误，但默认那个错误会使得重建停止阵列完全不可用，而不只是忽略某一小块，其实对于阵列卡可配置
  * RAID10：至少需要4块盘，先两两组1，再组0。进行增加容量时再加两块组1和0，很容易；不过另一种说法是组合模式不允许增加
  * RAID 1E(增强型)：支持3块盘，写入某文件后在下一块盘写入镜像，下一次写入文件在下一块盘，镜像在下下盘，空间利用率始终为总容量的50%
  * 所有盘的大小都必须相同
  * 木桶效应：要等最慢的那块盘写入完成
* 动态磁盘：过时技术。包括跨区卷（简单把多个卷拼在一起，按顺序写，大小可不同）、带区卷（相当于RAID0）、镜像卷（相当于RAID1）、RAID5卷（Server才能创建）。不能用于系统盘；重装windows后可能导致阵列丢失
* 存储池：win10后推荐。“复原”支持 简单（无复原）、双向镜像、三向镜像、单奇偶、双奇偶。先在多个盘上建立“存储空间”，设定复原方式，再创建普通的卷。支持后期添加硬盘。不支持RAID0模式，不能用于系统盘。refs在这上面才能发挥作用
* Intel VMD：在CPU内部集成了一个“虚拟控制器”，在BIOS里启用，系统要装RST驱动。开启后可以组RAID、热插拔。但这种固件RAID如果出故障很难恢复，还会消耗CPU。AMD的软件的GUI部分叫RAIDXpert2。Linux一般用ZFS纯软RAID
* 备份3-2-1原则：3份数据（1原2备），保存在2种介质上，1份保存在异地
