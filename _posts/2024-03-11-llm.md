# LLM

* FP32：就是普通的float。FP16：精度稍差，数字范围变为±65000。BF16：精度更差，但保留了FP32的数字范围，只有3060后才支持，IntelXeon3rd也支持。混合精度：平常用FP16，在加法用32。TF32：只有A100支持
  * torch_dtype：pytorch在不指定时会默认转换到float32。预训练模型指定auto会从参数中读取，一般是torch.bfloat16。在CPU上bf16是float32的2倍耗时
    * 查看类型：next(model.parameters()).dtype或pipe.torch_dtype
  * 大多数游戏GPU，FP64的性能是FP32的1/32

* 概念
  * 原始模型只是续写。Instruct版每个模型有不同的prompt模板，主流是ChatML
  * temperature和top_p：调小会更保守更有确定性，调大会有创意更发散。一般只调其中一个。例如对于答案是唯一确定的场合（翻译）temp用0-0.3，写文章用0.5，写广告用0.7
  * repetition_penalty：好像一般设为1.05。llama.cpp里叫--repeat-penalty
  * frequency_penalty和presence_penalty：后者是一直有效的，增大则会减少输出已存在过的词的概率，有助于讨论新主题；前者惩罚频繁使用的词，但仍可能从AAA变到ABABAB

## PromptEngineering

* C.O.S.T.A.R. 框架：Context背景信息 Objective目标任务 Style写作风格 Tone语气（正式、友好、幽默） Audience受众 Response Format响应格式
* In the context of xxx, 实际问题。Act as an expert on xxx。减少输出：be very brief/concise
* 区分指令和内容：Summarize the text **delimited by triple backticks(quotation/XML marks)** into a single sentence
* 结构化输出：Provide content in JSON format with the following keys: aaa, bbb。Foramt your response as a list of items separated by commas。Make your response as short as possible。Respond only with code, and with no markdown formatting或Return only the code in your reply. Do not include any additional formatting, such as markdown code blocks
* 检查条件：If the text contains xxx, action. If not, simply write \"No info provided.\"
* few shot 续写：Your task is to answer in a consistent style. <角色A>: xxx. <角色2>: xxx
  * 反思：现在存在两个角色，翻译家将英文翻译成中文，保留原本意思；校对家对于原文和译文找出不足之处并按中文习惯润色。步骤：先输入原文，翻译家翻译输出，校对家再输出
* 提供参考文本，要求将提供的材料原文引用出来，可减少幻觉
  * Use the below article about xxx to answer the subsequent question. If the answer cannot be found, write "I don't know."
* meta-prompt：一个用来创建或修改prompt的prompt，一般各产品的Agent中提供了此功能。OpenAI给出的版本：见docs中的prompt-generation
* COT：think step by step、explain your reasoning，但对于o1不需要，可用Only supply your reasoning at the beginning and end, not throughout the code. Make a plan for the directory structure you'll need, then return each file in full

## transformers

* 安装：transformers[torch] accelerate(device_map='auto'，会自动选用cpu或cuda，支持多张显卡，显存不够时会自动用内存)
* pipeline支持的任务：https://hf.co/docs/transformers/main/zh/task_summary
  * text-generation：又叫Causal Language Modeling。包括聊天机器、完成句子、内容生成。是decoder-only架构，包括GPT、Llama、Mistral、Falcon
  * Text-to-Text Generation：又叫Sequence-to-Sequence Modeling。包括翻译、问答、总结、自动更正。是encoder-decoder架构，包括T5、BART、Marian
  * Encoder-only：包括Bert。用于分析内容，如情感分析、主题分类、信息提取

```py
from transformers import pipeline

model_id = '本地模型文件夹' # 也称为checkpoint
pipe = pipeline('text-generation', model_id, torch_dtype='auto', device_map='auto') # 可任意指定其它参数，会应用到后续调用中
# pipe()的第一个参数是inputdata；也能接受迭代器返回迭代器，此时一般还调整batch_size

user_input = 'Who are you'
message = [
    {'role': 'system', 'content': 'You are a helpful assistant.'},
    {'role': 'user', 'content': user_input}
]

outputs = pipe(message, max_new_tokens=256, do_sample=True, temperature=0.6)
text = outputs[0]['generated_text'][-1]['content']

# 继续对话
chat = outputs[0]['generated_text']
chat.append({'role': 'user', 'content': user_input})


# 手动创建使用
model = AutoModelForCausalLM.from_pretrained(model_id).to(device)
tokenizer = AutoTokenizer.from_pretrained(model_id)
formatted_chat = tokenizer.apply_chat_template(message, tokenize=False, add_generation_prompt=True)
inputs = tokenizer(formatted_chat, return_tensors='pt', add_special_tokens=False).to(device)
outputs = model.generate(**inputs, max_new_tokens=99)
text = tokenizer.decode(outputs[0][inputs['input_ids'].size(1):], skip_special_tokens=True)

# from_pretrained 支持加载并转换tf模型到pt：from_tf=True
# apply_chat_template tokenize默认True，仅得到tensor。而设为False传给tokenizer()得到{input_ids, attention_mask}，传给generate可以**解包
# tokenizer
  # 第一个参数接受list或str，若为list，要加padding=True统一长度。其他参数：max_length=512 truncation=True
  # add_generation_prompt：添加 <|im_start|>assistant\n 引导模型续写回复
# max_new_tokens：具有默认值20，一般要指定否则基本无法输出
# model() 不用generate，效果是生成一个词。do_sample在这一步
# outputs 即使generate只传入一条消息，也会返回list[响应tensor]，一般取[0]获得唯一的响应。截取去掉输入的prompt，decode。如果有多条消息，用batch_decode()

from transformers import TextStreamer
streamer = TextStreamer(tokenizer, skip_prompt=True, skip_special_tokens=True) # 重用
model.generate(..., streamer=streamer)

# 界面
import gradio as gr
gr.Interface.from_pipeline(pipe).launch()
```

## 量化

* 分类
  * 训练后量化(Post Training Quantization, PTQ)：量化预训练好的模型
    * weight only、dynamic、static
  * 量化感知训练(Quantization Aware Training, QAT)：在训练或进一步微调之前执行量化。如QLoRA（就是量化+LoRA）
    * 目前的量化算法基本都能配合PEFT。但quanto除外
  * 有一种说法是QAT需要大量训练成本，对于LLM不能接受
* 效果：AWQ > GPTQ > bnb
* GPTQ(AutoGPTQ, auto-gptq)采用int4/fp16 (W4A16)的混合量化方案，模型权重被量化为int4，而激活值则保留在float16。在推理阶段，模型权重被动态地反量化回float16。也支持int8
* AWQ：仅有int4，torch_dtype仅为float16。推理时最好使用AutoAWQForCausalLM.from_quantized()，具有合适的默认参数。支持CPU推理(use_ipex)
  * https://qwen.readthedocs.io/zh-cn/latest/quantization/awq.html
* bitsandbytes(bnb)：可用于非文本（多模态）模型，可在线量化（On the fly）无需先单独转换（但也可以保存），load_in_4bit=True。简单，零样本
* optimum-quanto(不要装quanto)：HF出的，兼容torch.compile，支持cv模型，支持在线量化，支持CPU。HF网页文档与github上的不同，如果直接用pytorch或想保存则看后者
  * 不支持MinGW，实际是因为pytorch不支持；其中将IS_LINUX=True且IS_WINDOWS=False更有希望，将一处`replace(':', '$:')`启用后，ninja的构建报找不到`torch/extensions.h`，但明明参数里已经有了`-isystem xxx/torch/include`且单独运行找得到。另外调试时中断会导致Lock文件不删除无限等待
* optimum-intel
  * 具有三个子项目neural-compressor、openvino、ipex。但感觉作用都差不多，都是量化成自己的格式，再替换某个import运行。前两者还说可以剪枝和知识蒸馏
  * Neural Compressor：optimum-cli inc quantize。基于块结构化稀疏性，支持主流DL框架；支持Intel硬件，通过onnx支持其他GPU。安装依赖非常多，光本体就会装pillow opencv pandas scikit-learn
  * openvino：optimum-cli export openvino 转换到openvino格式，可以顺便量化。对于openvino来说专注于推理
    * quantization_config=OVWeightQuantizationConfig(bits=4,quant_method='awq')
    * 特别提到了支持SD
* intel/auto-round：自己宣传比awq好。Neural Compressor中集成了此算法。依赖peft

## 微调

* 按规模：PEFT(Parameter Efficient Fine Tuning)低参微调，Full Parameter Fine Tuning全参微调
* 按训练流程：SFT(Supervised Fine Tuning)有监督微调，IT(Instruction Tuning)指令微调是SFT的特殊形式，RLHF(Reinforcemnet Learning Human Feedback)人类反馈强化学习，包括DPO直接策略优化（用函数打分），PPO近端策略优化（训练一个打分模型）。不改变参数：In-Context Learning。SFT和RLHF又称“对齐Alignment”
* PEFT算法：LoRA、Prefix Tuning(P-Tuning v2)
* 教程：https://hf.co/docs/transformers/main/zh/training https://datasciencedojo.com/blog/fine-tuning-llms/ https://www.kaggle.com/code/hhoang41/llama-2-fine-tuning-using-qlora https://github.com/huggingface/transformers/issues/31332 https://generativeai.pub/a-beginners-guide-to-fine-tuning-mixtral-instruct-model-7f6a30aacf61 https://discuss.huggingface.co/t/fine-tune-and-then-successfully-awq-quantize/73239 https://gist.github.com/younesbelkada/f48af54c74ba6a39a7ae4fd777e72fe8 https://github.com/yangjianxin1/Firefly
* 工具框架
  * LLaMA-Factory：https://qwen.readthedocs.io/zh-cn/latest/training/SFT/llama_factory.html
  * LoRA能单独输出微调的部分，之后与基础的合并，方便已有基础镜像的人快速获得微调后的
  * Axolotl：简化微调流程。ChatLearn, Firefly, modelscope/ms-swift, XTuner, Liger Kernel, unsloth
  * TRL：一站式解决SFT(hf，SFTTrainer接受LoraConfig)、RM(Reward Modeling)、PPO，能自动将数据集格式化为chatml格式
    * trl chat --model_name_or_path HuggingFaceTB/SmolLM2-135M-Instruct --device cpu
  * torchtune：pytorch官方的微调框架，但目前只支持llama mistral gemma，7B+QLoRA消耗8.5G VRAM
  * https://github.com/stanfordnlp/dspy 优化权重

## llama.cpp

* 专门转换GGUF的：https://hf.co/TheBloke 一般下Q5_K_M或Q4_K_M。i系列量化时需要校准，4bit以下比k好，但只有40系才不会掉速度
* Realse版本区别：CPU推理用avx2；不知道是否可用openblas，可能依赖系统中的。vulkan和kompute好像是同类的，都支持某些NV和AMD。cudart含有CUDA运行时当系统里没装时才用，否则用cuda版。IntelGPU用sycl，内部用了oneAPI。AMD(ROCm)用hipBLAS。linux只有唯一选择用的CPU
* 简单模式
  * llama-simple-chat -m 模型.gguf 进入交互模式，第一次由用户输(-if/--interactive-first)。不会显示环境信息，相当于-co -cnv
  * llama-simple -m x.gguf "prompt" 给模型输入prompt后让它续写，无法进行交互。可选-n
* llama-cli详细选项
  * LLAMA_ARG_MODEL：指定-m
  * -n 要输出的token数，默认-1无限适合Chat
  * -c context length默认4096，指定0表示从模型中读取
    * --keep 保留最初的token数
  * -co(--color) 用不同颜色区分用户输入和模型输出
  * -t 要使用的线程，似乎默认等于当前CPU线程数且最大10，推荐改为物理核心数
  * --prompt-cache cache.bin 缓存最初的状态加快启动。只有指定了-p才有效
  * -f 从文件中读取prompt
  * --temp 0.8、--top-p 0.9【默】
  * --repeat-penalty 1.0即禁用 --no-penalize-nl 作者说对于Chat模型不应启用重复惩罚
  * -cnv 对话模式，不显示prefix和suffix，使用默认聊天模板，从模型内读取
    * 对于qwen，相当于：`-p "<|im_start|>system\nYou are Qwen, created by Alibaba Cloud. You are a helpful assistant.<|im_end|>\n" --in-prefix "<|im_start|>user\n" --in-suffix "<|im_end|>\n<|im_start|>assistant\n"`
  * -fa(--flash-attn) GPU版可用
  * -sp Show the special tokens
  * -ngl 层数 控制把多少层放到GPU里。但实际上即使只有1层放到内存里也会造成重大性能损失

### 函数(工具)调用

* 按指定格式将函数信息写成schema，传给create的tools参数。如果LLM决定调用tool，finish_reason等于'tool_calls'，message.tool_calls[0]指定了要在本地调用的函数名、参数、id；好像没有一般的回复。保存历史纪录user和{role:tool, content:函数输出, tool_call_id}，再chat
* f1={name, strict:true, description, parameters{type:object, properties{argname{type, description, 可选enum限制参数值}}, required[argname]}}; tools=[{type:function, function:f1}]
  * 其他创建方式：openai.pydantic_function_tool、transformers.utils.get_json_schema
* 默认支持“并行调用”，即可能调用多个函数。还可设置强制调用和不调用
* https://github.com/openai/swarm 是chat.completions的封装。功能一：方便创建函数调用，不用自己写schema。功能二：若return另一个Agent，则可创建类似pipeline的处理过程
* 本质还是把函数信息生成某种prompt，存在许多问题。可以在system_prompt里写用户询问某些问题时(何时)调用某个函数、在调用f1之前先调用f2
* 结构化输出，是JSON模式的改进：分为工具调用的参数(本质是LLM输出了那些参数)和一般的响应(指定response_format)。对于PySDK，都能用Pydantic自动生成，见openai-python的helpers.md，有个beta的parse()是create的包装，自动处理返回值生成指定类型在message.parsed。如果拒绝回答，信息在refusal里
  * JSON模式：response_format={"type":"json_object"}且必须在system_prompt中要求以JSON格式回答

### 其他能力

* 生成文字、生成图片（dall-e-3仅支持文生图，2支持修改区域和产生变种）、声音（TTS和STT有专门的优化模型，通用声音模型支持文字和声音配合）、Moderation审核(分类)文本和图像可以免费用
* embedding模型的用途：检测文本相关性。搜索、分类（好评差评）、聚类、推荐、异常检测（识别关联度较低的异常值）、多样性检测。有参数减少输出向量的长度(维度)，且大模型减少后表现仍比老模型未减少好
  * 距离函数：选用cosine-similarity，跟欧几里得距离排名一样，速度更快
* Assistants API：有状态，可访问持久的Thread，可使用预定义的工具
* output tokens：对于prompt的单次最大输出，如16k。context window：input+output的最大长度，如128k
  * 显示token划分：https://platform.openai.com/tokenizer 本地用库计算历史可避免超限
  * 输入的token不太影响延迟，而长输出会影响，因为原理上token是一个个产生的
  * 要求结构化输出时减少token的一种方式：将长字段描述改为注释，这样就不用生成
* 其他选项
  * 有选项将输入保留在Platform里，保存30天。可用于评估、微调蒸馏
  * n和best_of：默认都是1，n表示返回多少个回答，best_of表示生成多少个
  * seed：设为定值后，即使temperature不为0（但要固定）也会输出相同内容
* 处理vector：client.beta.threads.runs.create_and_poll()、client.vector_stores.file_batches.upload_and_poll()
* https://github.com/openai/CLIP
