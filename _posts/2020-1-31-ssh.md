## 命令行

* 安装：sudo apt-get install openssh-server。安装后会开机自启，关闭用`systemctl disable sshd`
* `ssh user@ip -p(port) '要在远端运行的命令'`
  * 如果需要交互必须加-t分配tty否则会失败
  * 执行本地脚本并传参数，其中若要传参则bash -s不可省：`... 'bash -s' < test.sh helloworld`
  * 执行远程脚本用绝对路径加参数
  * 从远端把数据传到本地，在后面加管道符号：`ssh .. 'tar cz src' | tar xz`。从本地传到远端就在前面加管道
* -v显示详细信息，-vv和-vvv更加详细
* 修改PAM后不需要reload sshd，在下一次登录时会自动使用新配置；使用错误的PAM配置覆盖后，下一次登录会立即失败
* 从参数、文件、环境变量中指定密码：sshpass 第三方库，但不更新了

## 公钥登录

1. 生成密钥：没有特殊情况，直接运行ssh-keygen，交互式按两下回车，就生成了~/.ssh/id_ed25519
  * 非交互式：`ssh-keygen -N "" -f "~/.ssh/id_ed25519" -t ed25519 -a 100`
  * N是密码，一般为空。-C可添加Comment，默认为user@host
  * pwsh下会说Too many arguments，看起来没识别空密码
  * rsa用`-t rsa -b 4096`。通过windows-hello验证加密的：ed25519-sk
2. `ssh-copy-id user@host`或`ssh user@host 'mkdir -p .ssh && cat >> .ssh/authorized_keys' < ~/.ssh/id_ed25519.pub`。win下前者不自带后者会失败，可用wsl。或vim编辑authorized_keys把内容打上去
3. chmod 700 .ssh; chmod 600 .ssh/authorized_keys

## CI添加私钥用于push

1. 公钥添加到repo的deploy keys里，勾上允许写
2. 私钥在本地：base64 -w0 id_rsa，会获得一整行数据
3. 添加进CI的环境变量
4. `echo $SSHKEY | base64 -d >> ~/.ssh/sshkey`
5. chmod 400 ~/.ssh/sshkey
6. ssh-add ~/.ssh/sshkey

## [~/.ssh/config](https://www.ssh.com/academy/ssh/config)

* 临时指定选项：命令行连接时用`-o "abc 123"`或`-oabc=123`
* 在第一次连接时不交互式确认添加公钥记录：`ssh -o "StrictHostKeyChecking no" -T`

```conf
ServerAliveInterval 60 # 默认0表示不发送。本来默认已有TCPKeepAlive yes，但是发空ACK可能被防火墙拦截
ConnectTimeout 15 # 设定TCP握手超时，默认约1-2分钟
Compression yes # 命令行中用-C；在局域网中最好关闭。Win11(v8.1+)可用

Host DebianVM
    HostName 192.168.98.129
    User debian
    Port 22
    # IdentityFile ~/.ssh/id_ed25519 # 如果不加会自动寻找所有默认命名的密钥文件
    # IdentitiesOnly yes
    Ciphers aes128-gcm@openssh.com,chacha20-poly1305@openssh.com # 用ssh -Q cipher可查询所有支持的
    # SendEnv LANG LC_* # 不清楚是否需要sshd中AcceptEnv

Host *
    # 用作Fallback，放在末尾
    # 一个Host指令标志着一个区块的开始，直到遇到下一个Host或Match指令。缩进无意义
    # 如果一个指令放在最前面，则后续Host里的同指令不会生效

# 连接server1.server.local时先连接jumphost.server.local
Host jumphost
    HostName jumphost.server.local
Host server*.server.local
    ProxyCommand ssh jumphost netcat -w 120 %h %p # 或 ProxyJump jumphost，命令行：-J user@ip

# 代理
ProxyCommand nc -v -x 127.0.0.1:1080 %h %p # socks5：-X 5
ProxyCommand c:/tools/connect.exe -H 127.0.0.1:1080 %h %p # 必须完整路径；不能用-S否则否则会询问socks密码

# 连接共享复用。自动维护UnixSocket
ControlMaster auto
ControlPath ~/.ssh/connection-%r@%h:%p
ControlPersist 4h
```

## [/etc/ssh/sshd_config](https://www.ssh.com/academy/ssh/sshd_config)

* 服务端的配置，部分选项也可用于客户端
* 修改完后必须重新载入配置：`systemctl reload sshd`，已有连接不会断开（restart也如此）
* 更好的选择是修改/etc/ssh/sshd_config.d/*.conf，并在主文件Include进来（最新版配置默认有）
* 第一次使用创建服务端证书：ssh-keygen -A。以下假定只有ed25519

```conf
Port 233 # 可以多次使用该指令监听多个；不清楚能否用逗号
PasswordAuthentication no # 禁止密码登录，只能用已有的密钥验证
#ListenAddress ::
#ClientAliveInterval 30 # 服务端定时向客户端发送心跳，还有ClientAliveCountMax默认3。用于断开无效客户端占资源。如果不设置，依赖系统TCP检测。如果为了保活，一般客户端设置

Ciphers aes128-gcm@openssh.com,chacha20-poly1305@openssh.com # 默认允许所有支持的加密方式，优先chacha20；设定后如果客户端不支持则无法连接。但有视频说服务端的顺序无效，只是支持的集合，按客户端发送的顺序处理
KexAlgorithms curve25519-sha256@libssh.org
#无需设置：AEAD隐含了MAC，etm意思是encrypt-then-mac更安全。HostKeyAlgorithms当存在多个key时优先使用哪个算法的。PubkeyAcceptedKeyTypes似乎不生效。HostKey指定服务端密钥，默认加载/etc/ssh/下预定义的

#PermitRootLogin 默认prohibit-password，可设为no（Cent可能默认它）。相关的还有AllowUsers和DenyUsers，支持限制地址。无法使用/etc/hosts.deny，它必须配合第三方库TCPWrappers
#Banner <文件> # 连接成功时显示文件中的信息；默认还会显示/etc/motd中的信息，不知哪个在前还是就是默认值
#X11Forwarding 默认no
#UseDNS和GSSAPIAuthentication 一般且默认no：服务器会先根据客户端的IP地址进行DNS PTR反向查询出客户端的主机名，然后根据查询出的客户端主机名进行DNS正向A记录查询，并验证是否与原始IP地址一致，通过此种措施来防止客户端欺骗，会降低连接速度
#LoginGraceTime 客户端连接后要在多久时间内完成登录，默认2m。相关：MaxAuthTries
```

## Forwarding转发

* 一般加`-CqTnN`：-q安静模式，-T禁止远程分配终端，-n关闭标准输入，-N不执行远程命令，-f要求后台运行（隐含n）。不加会像普通那样登录进去，只是额外加了转发
  * 已知不加q也没什么消息。且-R如果因为本机休眠而导致连接失效，终端里没有任何提示。C应该没必要开
* `ssh -D 1080 server`：Dynamic Forwarding。其实是Socks正向代理，监听本地8080的数据，通过ssh变由远端发送。因为Socks特性无需指定远端发送的目标
  * server设为自己，则将自己变为代理服务器
* `ssh -L 127.0.0.1:8080:intra:80 gw`：Local Forwarding，将访问本地8080的请求变为gw(跳板)发往intra(内网)的80
  * 映射远程端口到本地：intra填localhost，效果就好像gw的服务在本地开起来了一样
  * 堡垒机：intra只能从gw访问，gw可被公网访问。此时intra的端口填22，本机用此命令映射完后，再用ssh连接8080，输intra的密码
  * 第一个IP不加时可接受其它机器的请求（TODO:AI说不加时是localhost），则本机也是个跳板，但其它机器和本机之间的通信是TCP不经过ssh，此时本机类似反向代理服务器
* `ssh -R 8080:localhost:80 public`：Remote Forwarding，其它主机访问public的8080端口的请求转发到本地的80端口上。类似本机无法从公网访问时的内网穿透
  * 默认只允许转发从远端机器主动发起的请求，可用`GatewayPorts yes`允许所有的；或值用`clientspecified`，则客户端可在远端端口前加IP作为白名单
  * 远端端口可设为0，则会随机分配，客户端在连接时用`-O forward`就会把分配了的打印出来
* 服务器不能关闭AllowTcpForwarding
* 在客户端设置`ExitOnForwardFailure yes`能使转发失败时退出；默认是no
* -w 0:0：创建点对点IP隧道，用于非tcp/udp流量，需tun模块和root，需要PermitTunnel

## SSH Agent

* ssh-agent：`eval "$(ssh-agent)"`可以在后台启用，使用ssh开头的命令前要保证这个正在运行
* ssh-add只是临时的，退出shell环境（其实是ssh-agent）就会消失。永久添加需要在config中加`IdentityFile`
* 删除对应主机记住的密钥：ssh-keygen -R domain.com
* 客户端配置ForwardAgent，默认为no，好像有安全注意事项

### [cowrie](https://github.com/cowrie/cowrie)

* `docker run -d -p 22:2222 --restart always cowrie/cowrie`
* 直接使用是一个medium interaction SSH蜜罐，高交互模式叫做Proxy和Backend Pool
* 也支持Telnet(23:2223)
* 可在（docker容器的）`etc/userdb.txt`中添加可登录的用户名和密码，文件格式见`etc/userdb.example`
* 默认配置在`https://github.com/cowrie/cowrie/blob/master/etc/cowrie.cfg.dist`
* 最大的特点是支持输出成一些日志分析工具的格式，支持输出到mysql和mongodb；支持记录攻击者上传的文件（在`var/lib/cowrie/downloads/`）；提供了工具把内容复制到虚拟文件系统中，还有几个假的文字命令

## Windows版

* dism /Online /Add-Capability /CapabilityName:OpenSSH.Server。默认不会自启。服务端配置和服务端密钥位置：%ProgramData%\ssh，运行sshd自动生成
  * 追求新版：https://github.com/PowerShell/Win32-OpenSSH msi安装后自动启动sshd和agent
  * 可直接用windows的用户名密码登录
  * 密钥登录：客户端公钥放到 服务端配置\administrators_authorized_keys。客户端必须指定-i否则优先用win的账密
  * Server2025默认已安装，但未启用服务
