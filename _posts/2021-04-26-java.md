### 命令行

* 编译
  * javac -Xlint -g -cp lib.jar:pkg/* -d bin src/com/xxx.java，编译成bin/com/xxx.class（实际是因为package语句）
  * 若CWD为src，用 -d ../bin com/xxx.java
  * linux可用 `src/**/*.java`
  * 为老JRE编译 --release 8 要求源码只能用JAVA8的，不会检查库兼容性
  * Win的cp分隔符为分号
  * 不加-g没有局部变量名，仍有行号和源文件信息
* 运行class：java -cp a.jar:pkg/*:bin com.Main，即指定main()所在的完整类名，不是指定.class文件
  * cp默认为.（CWD）
  * VM运行选项必须在运行目标前，可用JDK_JAVA_OPTIONS环境变量设置，对运行jar也有效
    * 老版可用JAVA_TOOL_OPTIONS，对所有jdk工具都生效。新版用上一个，只对java命令有效，且会阻止设置MainClass或jar或-h
    * -ea启用assert语句
    * XX:+ShowCodeDetailsInExceptionMessages空指针异常时显示更详细的信息，但JDK15后默认启用了
  * java命令行现在也能直接运行xxx.java，但好像无法导入模块化的依赖，且main()所在的类必须是第一个
* 打包jar cvf out.jar -C bin .
  * 其中f指定输出的文件，C更改工作目录
  * 列出jar中的文件：jar tf out.jar。显示模块化jar的依赖：df
  * 打包完成的jar的根就是com等，不是bin
  * 还可以打包出含有入口点的jar，用cef com.Main out.jar。然而如果依赖其它jar包，则必须手动创建MANIFEST.MF，写Classpath属性。运行时加-cp无效
  * 运行含有入口点的包：java -jar out.jar args
  * Error: Unable to access jarfile a.jar：看看是不是不存在a.jar
* 模块化
  * 目的：jar是class的容器，但并不关心jar之间的依赖。如果运行时少了某个需要的jar就会出问题。模块化是使得一个jar能够自动找到依赖的jar
  * 创建和com平级的module-info.java，都放在src下：`module 模块名{requires 模块名; exports 模块名;}`，隐式导入了java.base，其余的import了的库必须在这里声明，别的库想访问本模块的类（如反射）则必须在这里声明导出
  * 模块名与pkg名不必相同，一个模块可以包括多个package，一个jar只能有一个模块，自己的.java不能和module-info平行
  * 编译：普通地编译module-info即可。依赖的库可用-p pkg直接指定文件夹了；另一种方式是用-m 模块名 --module-source-path src。之后生成jar没区别
  * 运行：java -p pkg;out.jar -m 模块名，或-p bin -m 模块名/完整类名（此处的斜杠为字面量）
  * 生成jmod：jmod create --class-path out.jar或bin out.jmod。无法简写成cp，当out.jmod已存在时不会自动覆盖，生成的out.jmod无法运行，仅用于生成jre，感觉没啥用，不如jlink时直接指定.jar或pkg
  * 生成jre：jlink -p out.jmod --add-modules java.base,模块名 --output jre --strip-debug/-G --compress=2/-c=2 --no-man-pages --no-header-files。之后可用jre/bin/java -m 模块名 运行，或先用--launcher创建启动脚本。其中add-modules的内容用jdeps分析，用--print-module-deps输出成jlink接受的格式。JDK21推荐改用-c=zip-9。TODO: 不清楚怎么加依赖，需不需要把依赖的jar转换成jmod
  * 分析依赖：jdeps xxx.class或--module-path out.jar;pkg -m 模块名
  * import module：还在预览，类似于C#的NS
* jshell JAVASE：REPL，且自动导入所有标准库
* jpackage -n 项目名
  * 模块化项目：-p 模块路径 -m 模块名/完整类名
  * 非模块化项目：-i bin --main-jar out.jar
  * 创建含有jre和本项目exe的文件夹：-t app-image
  * 创建带有图形界面的安装程序，Win下还要装Wix：--win-dir-chooser --win-console --win-shortcut --icon i.ico
* jdeprscan dir/jar/class：扫描是否使用了废弃的API，设置--release 8可得到尽量少的结果。另一种做法是jdeps -jdkinternals
* keytool
  * GUI：https://keystore-explorer.org/

## 语法

* import导入类，可以用*，默认导入了java.lang.*
* package类似命名空间，顺序要与文件夹匹配；但不同maven包可以有相同的package，且内容感觉会合并，类似于Py的命名空间包。再加上幽灵依赖，用起来非常混乱了
* 一般一个文件只有一个public类，且要与文件名匹配
* 函数参数不能有默认值。可变参数数组定义用`元素类型...`
* 异常：Error是严重错误。除RuntimeException以外的异常是Checked Exception，一定要捕获，或在方法参数签名后加throws xxx，可加在main上；缺点之一是不能配合Stream。catch时可用`|`同时处理多个异常类型，C#无此功能
  * 替换Checked Exception的设计模式：如果只抛一个CE，可返回Optional，或另写一个用来检测条件是否成立的函数（如迭代器的hasNext()），当可能被并发访问或检测代价大时后者不适用
  * 异常也是类，要设计成附带更多的信息以便使用者处理，如越界异常记录index。尤其是CE
  * 复用标准库的异常类：IllegalArgumentException如参数要求正数、NPE、IndexOutOfBoundsException、IllegalStateException（没有其他更合适的时）、UnsupportedOperationException（一般是类implement了某个接口但其实又没有实现）
  * 原子性：调用方法抛了异常，对象仍然是可用的，一般保持调用前的状态。实现方式：不可变对象、先检查有效性再修改内部、在副本上进行操作、编写恢复代码（如数据库）。不一定能实现，如ConcurrentModificationException
* break和continue支持跳转到label处以跳出多层循环，但label必须紧贴循环语句前边，相当于对那一个循环做break或continue。不支持goto
* byte是有符号的，而C#是无符号的
* main：所在的类不必为public的，参数必须为String[]
* 所有的包装类都是Number抽象类的子类，不可变，用intValue()解包成int

### switch和模式匹配

```java
// 只记录java14的，不需要写break
String fruit = "apple";
int opt = switch (fruit) { // 表达式，有返回值
    case "apple" -> 1;
    case "pear", "mango" -> 2;
    case String s when !s.isEmpty() -> ... // 类型匹配+守卫，且null不会匹配进去。一般还需要一个同类型+无守卫的用于穷尽
    case null -> ... // 目前正在preview。传统上如果对象是null，会在switch一开始就抛NPE
    default -> { // sealed的接口无需此句
        int code = fruit.hashCode();
        yield code;
    }
}; // 要有分号

if (!(o instanceof String s))
    return;
// 运行在这个范围内使用s。但如果if中又用了o就不行了

o instanceof Point(int x, var y) // 匹配record，绑定多个变量，JAVA21
for(Point(...): points) // JAVA20

long l = ...; if (l instanceof int i) {l的范围在int之内，可以安全转换} // JAVA24
```

## 字符串

* 多行字符串为三个双引号，开始时必须要换行且此换行不算内容，以结束时的引号为对齐基准去掉前面的缩进，转义仍有效，不支持raw string
* 其它类型转换为字符串：String.valueOf
  * Integer.toHexString整数转为十六进制字符串无前缀。还有toBinaryString，通用的toString(i,radix)
  * String.valueOf(nullobj)为"null"，C#为""
  * String.valueOf(char[])：与传Object行为完全不同
* 字符串转为其它基本类型：Integer.parseInt，可设定基数，值的部分必须只是值。Integer.decode()支持解析前缀
  * Integer.getInteger与System.getProperty一样，是获得系统属性的值，垃圾命名
* 判断相等用equals；推荐用Objects.equals()，不用判断是否为null
* 取字符必须用charAt()，不支持索引器
* 函数
  * contains、[last]indexOf、startsWith、substring、isEmpty、isBlank
  * replace、replaceAll 正则
  * split(正则, limit=0) limit参数：用-1时是正常行为，默认0会在划分完后去掉尾部的空元素，用正数n表示最多划分n-1次
  * strip[Leading/Trailing] 如果只有ASCII字符也可用trim
  * formatted/String.format C风格，也可都用%s
  * toCharArray、getBytes；转为字符串用构造函数，第二个参数指定编码，默认是file.encoding的
  * lines 按换行符分隔返回Stream
  * chars 变为IntStream。codePoints 按码点变为Stream
  * contentEquals(sb)
* StringBuilder：和C#一样，不线程安全。但delete方法第二个参数是index而不是length、具有reverse()而C#无。StringBuffer更老单线程性能差多线程安全
* java.text.MessageFormat.format()：类似C#，但模式要先new出来
* StringJoiner：支持设定开头、结尾、分隔符。new出来，add，toString。一般String.join()更方便

## 类

* 复用构造函数在函数体内用this()；调用父类成员用super
* 类和接口的继承：extends关键字。实现接口：implements关键字。abstract class可以有字段
* 接口：可以有字段，隐式public static final。接口里的函数可以在声明前面用default关键字实现默认方法，但不能访问字段，可以访问私有方法
* 重写：@Override。默认public函数都是虚函数，这个注解只是帮助检查
* final关键字：用在未初始化的字段上和参数上相当于C的const，用在初始化了的字段上相当于C#的const，用在函数上会阻止重写（private函数都隐式final），用在类上阻止继承
* 没有访问修饰符的类和字段为package包作用域，能被同包的普通类和public类使用，无需import，不会被其它包import，等价于C#的internal；protected等价于C#的protected internal
* 对象初始化器：在类定义里裸写一个{}，会在每次普通构造函数前调用，能访问实例成员，当多个构造函数具有相同逻辑又怕忘了手动调用复用时可用
  * new时的双大括号：其实就是匿名类加对象初始化器。但由于能访问new了obj的类里的对象，如果将obj作为返回值传出去，有可能导致资源无法被释放
* 静态代码块：`static {...}`，类似于C#的静态构造函数
* static成员可通过实例对象使用，且对象为null也可以，不过会有Lint警告
* record Point(int x, int y) {}
  * 定位是命名元组，不是用于封装数据的
  * 自动生成构造函数、不可变成员、toString、equals、hashCode
  * 检查范围：public Point{if(x<0) throw new IllegalArgumentException();} 称为Compact Constructor，写不含参数的构造函数且无需自己给成员赋值
  * 在模式匹配中可用类似于构造函数的语法解构成员并使用，且可用var

* 让类支持try-with-resources：实现AutoCloseable接口的close()
  * Finalize()废弃了，用Cleaner机制替换。本质就是在另一个实现close()的类里注入本类（或者也可以实现在本类里），try(那个cleaner对象)。主要是可以一次性register多个，一起clean掉，以及在另一个线程运行资源回收
  * 当try中发生异常时，try-finally的finally也会执行，往往会产生新异常覆盖掉try的，但一般来说try的异常才是真正的原因。而try-with-resources会保留第一个异常
* 检查参数
  * Objects.requireNonNull(obj) 返回原本的obj
  * checkFromIndexSize()、checkFromToIndex()、checkIndex()
* JavaBean：getXXX、setXXX。boolean字段的getter的命名为isXxx
* 密封类，当业务上需要处理接口的每个实现时使用：sealed interface Ixx permits Xxx, Yyy

```java

        Objects.equals(this.name, p.name) && this.age == p.age && Double.compare(d1, d2 不会自动装箱且能处理NaN等)==0;

    return Objects.hash(firstName, lastName, age); // 会装箱，影响性能
    // 对于多个基本类型字段，EffectiveJava的建议写法：int hc=Short.hashCode(a); hc= result*31 + Short.hashCode(b); return hc;
}

// 比较：implements Comparable<具体T一般是自己>
```

### 注解

* 创建类型：@interface A{int i() default 0; String value() default "";}
* 可加@Target指定注解能用在什么上。@Retention指定生命周期，默认为CLASS，一般要改成RUNTIME，如果要反射获取值就要改。@Inherited使用时子类可以继承父类使用的
  * 如果目标类型是TYPE，想清楚是不是接口更合适，即使是无方法的

  * 如果字段是数组，则用{}，但单元素也兼容不用

* 与依赖于名称（如以Test结尾）相比，优先选注解
* 可重复注解：在一个对象上能应用多次。创建类型时再另外创建一个AContainer，value是A[]，A加@Repeatable(AContainer.class)。读取时，getAnnotationByType(A.class)，会返回A[]。但对于isAnnotationPresent来说是不透明的，一般要用||将A和AContainer都判断了

### enum枚举

* 可用==比较两个对象，可定义方法，可在类中用`实例名(参数),实例2;`创建枚举常量对象
* E.values()获得所有实例，valueOf("实例名")或Enum.valueOf(clazz, "实例名")从字符串转换，e.name()与未重写时的toString()相同，ordinal()略
* 不推荐依赖ordinal。如果需要数字到枚举值的映射，应将数字作为field，创建枚举常量时指定
* 不能继承，能实现接口，多个enum实现同一个接口达到扩展的效果
* 可用于实现单例模式：就把class改成enum，成员加一个INSTANCE;就好了。而且自带序列化机制。
* 模拟exhaustive匹配：添加一个abstract方法，创建枚举常量时用{匿名类实现行为}，新添加的常量如果没有实现会编译期报错。另一种需要复用行为的方式：创建一个“策略模式”内部enum，将不同行为实现为枚举常量（用前一种方式），外部enum添加构造函数要求指定行为
* 代替位域：本质上是接收多个选项，将选项实现为enum常量，使用者改为接收`Set<枚举类>`，传参时用`EnumSet.of(枚举常量)`

### 内部类

* 普通类不能用private，内部类才可以
* 如果内部类没有private，就也为包作用域，但在外部使用必须从外部类的对象实例化：`Outer.Inner inner = outer.new Inner()`
* 用static修饰内部类就不再依附外部类对象了，且仍可实例化new Outer.Inner()，编译后就是不相关的两个类。不存在C#的静态类的概念，外部类无法加static
* 内部类对象内部能直接访问外部类对象：`Outer.this.xxx`，能修改外部类的private成员。外部类对象在类中也能访问内部类的private成员
* 可用于Lazy单例模式：静态内部类(称作Holder)创建final static instance=C()，外面定义getInstance()返回inner.instance。非Lazy的单例一般用静态字段就好了
* 匿名类：`var obj = new 接口名或父类名(){类成员代码，无需public外部就可obj.访问}`，用于一个类中包含另一个类，且省去定义内部类再实例化。C#无此功能

## 泛型

* 目标：只要能无警告通过编译，就不在运行时产生ClassCastException。虽然擦除了，但外部在使用具体的T时编译器会插入cast
* 泛型方法
  * 与C#相比`<T>`需放在返回值前。调用时显式指明类型时放在方法名前
  * 静态泛型方法可声明于泛型类中，但调用时无需也不能具体化泛型类，实际与泛型类的T无关
  * 当想要运行时检查类型时，一般与`Class<T>`配合使用，使得传Class对象后不再需要指定类型，返回时用clazz.cast(obj)
* 不能放基本类型
  * 泛型方法自动推断时会变为对应的包装类型
* 不被类型擦除的类型称为reifiable可具化，否则称为non-reifiable。前者如数组意味着运行时知道元素类型且会执行约束；后者运行时所包含的信息比编译时少

### 类型擦除

* `new C<A>().getClass() == new C<B>().getClass() == new C<Object>().getClass() == C.class`
  * 不能写`C<A>.class`，类内不能T.class
  * 不能判断带泛型的类型 `o instanceof C<A>`，只能用`C`或`C<?>`；类内不能o instanceof T，但可t instanceof A
  * t.getClass() == Object.class
  * t[].class == Object[].class
* 不能new T()
  * 变通：函数参数加`Class<T>`，反射创建实例
* 不能 `new T[5]`
  * 一般不把泛型和数组混用，用List代替即可
  * 变通：`@SuppressWarnings("unchecked") field = (T[])new Object[]` 且传出类外的只能是其元素
    * 如果传出T[]，会编译期插入转换成具体类型如Integer[]的强转代码，但实际运行时是Object[]而抛异常。这种编译期和运行时类型不一致的情况称作“堆污染”
      * 泛型方法类似，如果允许：`static T[] f(T a){return new T[]{a};}; var arr = f(1)` 会编译通过运行时报错，T根据函数参数自动推断为Integer[]
  * 另一种方式：field = new Object[]，在取元素时每次强转成T，还是要加抑制警告。没有堆污染，但实际用的不如上一种多
  * 泛型可变参数，用得多，开了后门：`@SafeVarArgs (final或static <T>) T[] f(T... args){return args;}` 其实还是存在上面的问题，实践中不要把args传出去、不能override、不要往args里储存
* 不能new具体泛型类型数组 `new List<Integer>[5]`
  * 变通：`@SuppressWarnings("unchecked") List<Integer>[] l = new ArrayList[5]`。或反射创建：`(List<Integer>[])Array.newInstance(ArrayList.class,5)`
  * 原因：数组是协变的，无警告允许Object[] arr = new String[1]。若允许本项，现象：
    * `List<Integer>[] larr = new ArrayList<>[1]; Object[] oarr = larr; oarr[0]=new List<String>(){添加"s"}` 编译和运行时都不会报错，因为larr的运行时类型是List[]，可以接受`List<String和Integer>`；但larr[0].get(0)会运行时报错，因为会自动插入将Object转换为Integer的代码，但实际上它是String
  * 可以正常创建基本类型数组的泛型类`new List<int[]>()`
* 重载：不能同时声明 `f(C<A> c) f(C<B> c)`
  * 不能同时声明 `C<T1> C<T1,T2>` 两个类，因此做不出C#的Func
  * 声明equals(T t)擦除成equals(Object)导致与继承自Object的冲突；不过equals参数用T没实际意义
* 若子类继承了具体泛型的父类
  * 可以反射获得具体泛型。如`new TypeReference<Integer>(){}`匿名(子)类的对象
  * 桥方法：对于`D extends B<Integer>`，若D重写了B的泛型方法，理论上B的T擦除后是Object，而D重写的类型是Integer，就会形成重载而非override。但实际上会按正常思维那样调用，因为编译器自动生成了桥方法
* 静态
  * 类的静态字段类型不能是T
  * 泛型类中的静态非泛型方法，不能使用泛型类的T。变通：声明为泛型方法，且使用时显式指定

### 泛型约束：泛型定义中`<T extends R>`

* extends A & B：取二者子类型的交集，同时实现了AB接口
* `<T extends Comparable<? super T>>`，则可用t.compareTo()
* 模拟self类型(self-type pattern)：抽象父类`B<T extends B<T>>`，且具有`protected abstract T self()`。子类`D extends B<D>`且实现self()返回this。这样子类能继承父类中带有T的函数，且此时T就是子类这个具体类型。其中父类的泛型T的约束可理解为任何继承了父类的类，即子类

### 可变性

* 使用者写在函数参数或变量的类型**声明**后，可直接用于类；不是放在类和接口的定义上。编译器根据此变量的方法中T所在位置限制允许使用的方法
* 协变Covariance用`类型名<? extends 具体类型>`，称为上界通配符；逆变Contravariance用super
* 如Animal是Dog的父类，如果有某种变换f，f(Animal)是f(Dog)的父类，则称为协变；如果是子类，则称为逆变
* 比C#更灵活，因为可以不用类作者更改代码
* 例子
  * `List<? extends String>`表示只读集合，但仍能调用add(null)。用super可表示只写集合，仍能用get()但只能赋给Object
  * `static <T> void copy(List<? extends T> src， List<? super T> dest)`：不修改src，不读取dest。PECS原则(Producer Extends, Consumer Super)
  * `Comparable<? super T>`
  * `Class<? extends T[]>`表示要求它来自于任何数组，但传实参时不能用T[]对象的getClass()，否则等于Object[]
* `<?>` unbounded wildcard type 无限定通配符
  * 作为协变时与`<? extends Object>`同义，可get为Object。同时也是所有逆变的父类
  * 主要用于阻止add(o)，这也是与对应非泛型类的区别，但仍能调用add(null)
  * 一般可用无限制泛型方法代替它。不过如果T在泛型方法签名的所有地方只出现了一次，一般用它；如果用它且T有限制，则就是逆变协变，即逆变协变本质上就是泛型约束
  * 当处理逻辑不依赖T时使用，如List.size() clear()
  * 说是不会擦除，可以在instanceof中、可以作为数组类型；但又不能取.class

## 函数式

* 接口
  * 单方法接口SAM(Single Abstract Method)（但可有默认方法）用`@FunctionalInterface`注解（不强制使用，使用后如果有多个方法会编译期错误），可用Lambda表达式代替匿名类隐式实现接口（C#办不到）`(s1, s2) -> s1.compareTo(s2)`
  * 方法引用：用双冒号。可引用实例方法，则相当于隐式添加第一个参数this，如`String::trim`，C#做不到。构造器：C::new、C[]::new
  * lambda表达式闭包的变量要求是final的，可用MutableBox绕过，如`var o = new Object(){int i=0; int f(x){return i+=x;}}`闭包o，调用f()。MB也能用来模拟多返回值
* `Optional<T>`
  * 原意是替代null，但不可序列化
  * 创建者返回空时用Optional.empty()；一定有值时返回Optional.of(xxx)，如果xxx为null会抛异常；可能有值用ofNullable(o)

### 同步和互斥

* 理论
  * 不需要同步和互斥：单线程内的对象（不共享数据）、不可变对象（或完成初始化后不再修改）、内部做了同步（AtomicLong）
  * therad-hostile线程不利：即使客户端代码尝试通过外部同步机制来保护对该类的访问，它仍无法多线程下安全使用，因为另一个使用者完全可以不加锁访问而从破坏状态。是线程安全等级中最低的一种
  * 不应在互斥块里调用虚方法或外部传进来的函数，外部逻辑可能破坏不变式、死锁
  * happens-before：若A happens before B，则对A的写入，B能读取到；具有传递性。如其中一条规则：主线程设置了共享变量后start子线程，则子能看到；子设置了，主join后能看到
* synchronized
  * 一般在方法上加，相当于整个方法体synchronized(this)
    * 加在锁对象上，可控制一块范围：final Object lock = new Object()，使用时synchronized(lock){...}
  * 是可重入锁。无论是否有异常都会在结束时释放锁。用于互斥
  * 只在里面访问变量不需要再加volatile，能完全替代
  * wait和notify的惯用法：多个消费者synchronized(同一o){while(检查条件不满足) o.wait(); 使用o}，另一线程生产者o.notifyAll()。它们是native方法，wait时会释放锁
  * 原理：监视器锁Monitor Lock机制，有字节码指令。有优化，交替访问时用CAS，竞争访问时用重量级锁
* volatile：可见性、避免指令重排
  * 可见性：对于单线程下修改变量会存在寄存器里而不是内存里，导致另一个线程观测不到变量变化
  * 指令重排：如f(){v=1; ok=true}可能先执行ok，对于g(){if(ok)使用v}来说，单线程下才没问题。给ok加volatile即可避免重排；默认若数据存在依赖关系不会重排
  * 不保证原子性，如i++不是原子操作，即使加volatile，另一线程也可能观察到中间值。解决方法是用原子类，此时不再不需要volatile
  * 对于Lazy单例模式：一种方式是用双检锁+volatile，且创建一个local变量，两次检查前先把字段赋值到局部变量
    * 如果不用volatile，可能正在初始化的过程中还没完成，成员字段就不为null了被另一线程返回使用
    * 如果不在意重复初始化，可用单次检查法：只用volatile和一次检查null，不用synchronized
    * 如果不在意性能，可以在方法上加synchronized，也只用检查一次null
  * 如果用了final，可代替它
* 同步器
  * Semaphore：保护数量有限的资源，require和release
  * CountDownLatch：类似于Go的WaitGroup
  * CyclicBarrier：达到指定数量的线程后才开始同一时间执行。或看作可多次生效的CountDownLatch。还有个自定义程度更高的Phaser
  * Exchanger：类似于Go的阻塞Channel，但可以两者互相发数据
* AQS锁concurrent.locks
  * ReentrantLock：和手动使用synchronized差不多。要在finally释放。允许tryLock()指定超时，更不容易死锁；lockInterruptibly()允许线程被中断；默认非公平锁会竞争，new (true)改为公平锁按申请顺序
  * Condition：代替wait和notify，用法类似。必须从Lock中创建（对应wait必须在synchronized里），这样才能保证出循环时条件仍然成立；如果不需要这个保证（如配合并发队列），可用LockSupport.park()，且它不可重入
  * ReadWriteLock
  * StampedLock：与ReadWriteLock类似，但是读乐观锁，读时也允许获取写锁后写入，需要读完一条后validate()一下，如果发现有写入再加普通读锁重读。不可重入
* 原子类concurrent.atomic
  * 单条赋值语句，引用类型、除了long和double的基本类型，是原子的。long和double在x64上是原子的
  * AtomicLong和Integer：incrementAndGet()
  * AtomicReference：仅限引用类型，它的get()和set()和volatile效果一样，且提供更多功能如compareAndSet()
  * AtomicIntegerArray：其元素具有volatile语义
  * LongAdder：对自增友好
  * 手动控制已有的volatile变量：AtomicXXXFieldUpdater
  * 属于CAS(Compare and Swap)操作，乐观锁，具有ABA问题：两个线程分别取出值A，第一个线程改成B又改回A，第二个线程CAS操作能成功。解决办法(检测)：版本号，用AtomicStampedReference或AtomicMarkableReference；其中后者只用1bit检测，适用于最多两个线程并发

## GC调优

* G1最大暂停-XX:MaxGCPauseMillis默认200ms
* 当大量实例突然变得符合回收条件时，考虑用ZGC和SGC。当堆的很大一部分被持续占用时，用G1
* 现在64位的JDK只有Server模式，-client参数会直接忽略
* -Xmx512m：最大堆大小，默认为1/4的内存。ms是最小和初始堆大小，低于它的占用也不会返回给系统
  * -XX:SoftMaxHeapSize=1G：要求VM尽量不超过此值规定的最大堆大小，好像只有ZGC支持，不过这参数是JDK的，别的GC就算不支持也不会报错
  * -XX:MaxRAMPercentage=75：分配所有内存的75%，当在容器里运行且限制了内存时考虑使用。一般来说还是用Xmx且不限内存，因为程序需要多少内存应该由程序的功能决定
* -XX:+UseLargePages：大内存如16G时启用，还需设置/sys/kernel/mm/hugepages/hugepages-2048kB/nr_hugepages，值至少为16G/2M=8192。ZGC使用时内核最好大于4.14
  * Linux下考虑改用-XX:+UseTransparentHugePages，还要设置echo "madvise" > /sys/kernel/mm/transparent_hugepage/enabled; echo advise > /sys/kernel/mm/transparent_hugepage/shmem_enabled。相比之下某些时候能减少内存占用，但可能造成延迟抖动。内核最好大于4.7
* -XX:+AlwaysPreTouch：启动jvm时申请较多内存，能减少延迟卡顿
* 在GC时合并重复的字符串：-XX:+UseStringDeduplication JDK17及之前仅限G1，之后都支持
* -XX:+UseShenandoahGC：也是低延迟，适用于Web服务端。实测Win下内存占用很高。RedHat提供JDK8的
  * 分代：-XX:+UnlockExperimentalVMOptions -XX:ShenandoahGCMode=generational 至少JDK24
* -XX:+UseZGC -XX:+ZGenerational：延迟低；最好设置mx，一般最少16G，CPU负荷最好小于70%。借鉴了Azul的C4算法。JDK23默认分代
* 显示当前使用了哪种GC、GC参数、运行过程中的调用情况：-Xlog:gc+init+stats
* 查看当前选项包括所使用的GC模式：java -XX:+PrintCommandLineFlags -version。查看包括默认值在内的所有选项：-XX:+PrintFlagsFinal。
* 避免用户乱调用System.gc()：-XX:+DisableExplicitGC
* 不进行GC：-XX:+UnlockExperimentalVMOptions -Xlog:disable -XX:+UseEpsilonGC
* 禁用析构函数：--finalization=disabled JDK18后支持
* 内存泄漏常见原因：①长生命周期对象持有短生命周期对象的引用：自制stack，pop时没有将数组中的引用设为null；线程(池)未终止。②缓存。③监听器/回调未注销
* -XX:+UnlockExperimentalVMOptions -XX:+UseCompactObjectHeaders https://openjdk.org/jeps/450 至少JDK24

* With：类似于C#的record的
* 字段的第一个单词不要只有一个字母，如不要用cData
* boolean类型（不包括Boolean）会特殊处理，原意是对于isXXX canXXX shouldXXX这种形式的命名生成更人性化的方法，但缺点是不符合一般生成规律
* SneakyThrows：自动把CheckedException变成Unchecked

## FFM API(Project Panama)

* JDK22转正
* jextract：从C头文件中生成java绑定。--output src --target-package(-t) org.unix lib.h，会生成src/org/unix/lib_h.java。使用：mystruct.allocate(arena)。对不同目标机器可能要重新生成
* 阻止警告：--enable-native-access=ALL-UNNAMED
* VarHandle需要JIT具有overhead，如果只调用几次则选offset

```java
Arena：global生命周期无限。ofAuto等GC自动回收，用于legacy的ByteBuffer语义。ofConfined和ofShared用try-with-resources显式控制生命周期。只有Confined仅用于单线程，一般优先使用；Shared在关闭时很慢会检查和等待各线程写入完成，但访问时不慢适合并行流。是管理一组相同生命周期MS的方式，不是先划分大内存再从中划分MS
MemorySegment：语义为一块内存，包括起始地址和长度
  创建：arena.allocate(bytes或MemoryLayout)、allocateFrom(str)、allocateFrom(JAVA_INT, 初始化的数组元素...)
    不分配，只引用，因此不是用的arena的方法：MemorySegment.NULL、ofAddress(0)、ofArray(基元数组)是堆上内存
MemoryLayout：用Java对象表示C类型。最好用static final
  基元：ValueLayout.JAVA_INT，BYTE对应C的char，ADDRESS表示指针
  数组：MemoryLayout.sequenceLayout(length, elementLayout)
  结构体：MemoryLayout.structLayout(JAVA_INT.withName("x"), ...) 要自己加paddingLayout()，且结尾的也要
读写MS：
  基元：(int)seg.get(JAVA_INT, 0) 第二个参数是offset，其实可用于任何情形
  数组：seg.getAtIndex(JAVA_INT, ndx) 自动计算 偏移=类型大小*ndx，但本质是与get不同的另一条汇编。转换回Java：seg.toArray(JAVA_INT)
    另一种处理选择：elements(JAVA_INT)返回Stream<MemorySegment>，之后可以mapToInt(s->s.get(JAVA_INT,0))
  字符串：seg.getString(0) 自动处理\0
  结构体：VarHandle xh = LAYOUT.varHandle(PathElement.groupElement("x")).withInvokeExactBehavior(); xh.get(ms, 0L); xh.set(ms, 0L, value);
    结构体数组：varHandle(sequenceElement(), groupElement("x")); xh.get(ms, 0L, (long)ndx)
    解释：VarHandle的get参数是Object...，实际是根据PathElement创建的。第二个参数是基础offset，一般固定为0L，因为实际offset会自动计算。这样能处理每个数组元素中的x，感觉不太符合一般思维，可考虑改为先element()处理数组
    结构体数组另一种创建xh的选择：LAYOUT.arrayElementVarHandle(groupElement("x")); set(ms, 0L, (long)ndx, val)
  seg.fill(byte)、copyFrom(src_seg如ofArray的)，想指定offset和length用copy静态方法，或seg.asSlice()改变大小(是view)

调用外部方法：

(cast返回类型)f.invokeExact(参数)
upcall：将java函数作为回调传给C，不学
C标准库函数：Linker.nativeLinker().defaultLookup().find("free").get()。还有一个SymbolLookup.loaderLookup()，看演示会.or(前者)
可变参：不学

处理全局变量：
还是先用lib.find("symbol").get()获得符号的地址。只知道地址不知道长度，一般需先reinterpret()
基元类型：reinterpret(长度).get(类型, 0)
指针：reinterprete(ADDRESS.byteSize()).get(ValueLayout.ADDRESS.withTargetLayout(类型), 0).get(类型, 0) 第一个get相当于解引用
字符串本体：reinterprete(Long.MAX_VALUE) getString会处理到\0就停止
```

### 定时任务

如sleep(一段时间)再执行逻辑。因为不能阻塞主线程，所以要new Thread。\
但每个任务都新建Thread太消耗性能。如果用线程池，则最多存放n个任务同时sleep，后序就加不进了，所以不行。\
根本原因是想执行的任务逻辑只是一个Runnable。\
可以把所有任务放到优先队列中，单一守护线程等待下一个离待触发时间最近的，取出来放进线程池执行。如果有新任务添加，要重新计算最小等待时间。\
对于重复执行的任务，在结束时再添加一个新单次任务即可。
