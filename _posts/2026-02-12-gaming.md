# NV App

## 垂直同步

* 如果帧数是刷新率2倍以上，又想要低延迟，用三重缓冲（快速垂直同步）；但有网友说三重缓冲会增大输入延迟，只是不损失帧数
* 自适应 (Adaptive)：这是 G-SYNC 诞生之前的“穷人版 G-SYNC”。FPS 高时自动开启V-Sync防撕裂，FPS 低时自动关闭V-Sync（防卡顿，但会撕裂）
* 无边框窗口模式：通过了DWM，要调整G-SYNC“为窗口模式和全屏模式启用”，依赖游戏是否允许 DWM 传递 VRR 信息。现代 DX12 游戏的无边框模式延迟已经非常接近独占全屏了（启用"独立翻转模型"）。默认强制启用某一种垂直同步

## 3A设置

锁 刷新率-3 帧 + G-SYNC（需独显直连+全屏独占） + 关闭游戏内垂直同步 + 在App中开启垂直同步

说明：

1. G-SYNC只在不满刷新率时生效，大于等于刷新率时失效。如果帧率大于刷新率会全屏撕裂，开启V-Sync可防止（在锁刷新率-3时不靠它防止）。
2. G-SYNC生效时，只能解决“刷新开始时间”的同步，不能解决“扫描输出（Scanout）”过程中的偏差。结果是屏幕底部可能撕裂。
3. G-SYNC激活范围内驱动里的V-Sync不会像传统V-Sync那样强行让显卡等待，而是仅仅充当一个“守门员”。这消除了最后的底部撕裂，且只增加很少延迟。如果不介意底部撕裂可以不开V-Sync。
4. 如果在游戏里开启垂直同步，很多游戏引擎会在这个环节加一个“预渲染帧队列”。

## Reflex

* 需要游戏开发者集成，是App里“低延迟模式”的进化。在用G-SYNC + V-Sync时会自动锁帧，也能单独用或与G-SYNC用
* 如果CPU瓶颈则不要开，会导致帧数进一步下降。因为原理是启用后CPU->GPU线性依赖无缓冲，不启用时二者并行工作
* 显卡瓶颈则效果较好。但也会略微降低帧率，会强制显卡占用率<100%，因为显卡满载会产生更大输入延迟
* 低延迟模式不要全局启用，可能导致游戏卡顿、画面闪烁
* 输入延迟的概念：在有渲染队列且GPU瓶颈时，某些帧已经被CPU处理，未被GPU处理和显示，如果进行输入，则不会反映到那些帧上

## Smooth Motion插帧

* 对于RPG Maker游戏，配合Magpie可用。移动时产生果冻效应，对话文字会扭曲

## GPU System Processor

启用GPU内部的某些处理器，让原本一些需要CPU处理的改为GPU内部自己处理，能降低延迟。但如果显卡负载满了可能不会提升，适合低U高显的；笔记本显卡功耗本来就有限制，GPU耐热也比CPU低。对于机器学习有用

```
[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}\0001]
"EnableGpuFirmware"=dword:00000001
```

其中0000为核显，0001为独显，最好具体看一下内容。

验证：nvidia-smi -q 显示 GSP Firmware Version 不为N/A。

缺点：占用0.5GB显存（看FB Memory Usage的Reserved）。可能导致G-Sync失效、WebView2程序出问题。影响HDCP（播放受版权保护的视频的技术）、DSC。有网友说与intel核显一起用的时候会损坏GSP单元。

## 超分

* magpie：主用于galgame等老游戏，把低分材质放大。能把窗口游戏变为全屏
  * 如果你设置了 DPI 缩放，而要放大的窗口没有高 DPI 支持（这在老游戏中很常见），推荐首先进入该程序的兼容性设置，将“高 DPI 缩放替代”设置为“应用程序”
  * 一些游戏支持调整窗口的大小，但只使用简单的缩放算法，这时请先将其设为原始（最佳）分辨率
  * 不支持FSR2/3需要游戏引擎集成，只支持1的空间算法。不支持插帧，但可以配合NV smooth motion，但有bug，每缩放一次会额外占1G显存，多用几次就爆了
  * 用于动画的模型：ACNet（会降噪）、CuNNy、Anime4K。效果 Anime4K_GAN>ACNet。个人用CuNNy->Anime4K_Restore->xBRZ_2x
  * 配合smooth motion可以插帧，但每次缩放，已提交内存会持续累积
* lossless scaling 小黄鸭：给锁帧游戏插帧，要求原生帧高且稳定。也有FSR功能。游戏本身设置锁帧，用无边框，不能是全屏独占。支持所有程序。可以让核显插帧
* dlss-swapper：替换游戏的dll文件，让它支持新版模型。某些老游戏NV APP不支持替换。能自动检测Steam的游戏
* OptiScaler：让AMD硬件运行只支持DLSS的游戏，或老NV显卡运行不了DLSS4，将实际运行的算法改为FSR/XeSS开源算法。必须要游戏原生支持某种超分算法。网游不要用，可能被检测作弊。也支持帧生成
* https://github.com/artur-graniszewski/DLSS-Enabler 集成了OptiScaler，没看懂做了什么改进

对于笔记本，nvidia-smi -pl从525后不支持修改了，可以改用-lgc限制频率。

## 颜色输出

数字亮丽55-60，灰度0.95-0.9，调高显示器亮度。如果用RTX HDR，不要改此处的灰度。

# Special K

* 文档：https://wiki.special-k.info/
* 下载汉化版：https://juij.fun/#SpecialK（https://pan.quark.cn/s/8787896b395e）
* HDR
  * 支持游戏结束后自动关闭系统开关
  * 能可视化哪些部分亮度高
  * “启用全HDR亮度”关闭时会限制亮度到1000nit。亮度等级一般拉到最大值的1/2 - 2/3
  * HDR10用于开了帧生成的，其它情况用scRGB。Alt+Enter切一下窗口或重启生效
  * 管线重制remaster：在早期启用HDR而非仅仅后处理，效果更好，8位的最重要。只在dx11里有，可能游戏不兼容。右键，Keep 8/10-bpc Render Passes UNORM，当提示不兼容时使用
  * 中间灰：降低将增加动态范围，但会降低对比度。增加可能会冲淡游戏中任何包含人脸的用户界面部分
* 功能
  * 监控：帧率可显示波动，延迟可显示瓶颈。显示VRR状态
  * 锁原始帧（DX12设置 - DLSS设置 - Pace Native Frames）、强开Resizable BAR、调整DLSS预设
  * 增强Dx11游戏：无边框窗口模式的翻转模型（把全屏改为无边框，但win11好像自带）、texture修改和缓存
  * Tear-free no-sync (Latent Sync) 当VRR不可用时有用，锁帧到固定刷新率的整数倍，具有与VRR相同的延迟。菜单里关闭V-Sync后可配置。如果它控制V-Sync就不要用驱动控制了
  * 在不支持的游戏里使用Nvidia Reflex。Low Latency会启用帧率限制到略低于刷新率的几帧，Boost会启用最大性能电源模式
* 游戏模式：Win+G，设置里勾上 记住这是一款游戏，重启。之后Special K里的电源模式能看到游戏模式
* 配置：主界面（库）右下角配置文件，是每个游戏独立的；右键可重置某游戏的修改。Global\default_SpecialK.ini是模板。master_SpecialK.ini是覆盖独立的
  * AllowFlipMetering=默认false 注释说是阻止DLSSFG假帧的帧排序。如果改为true，网友说效果为：启用GPU硬件帧排序、无法开启SK的垂直同步、RTSS帧生成时间无法正常读取变为0.5ms、在假帧时按快捷键无法打开控制面板。不用SK时默认启用
* Ctrl+Shift+Backspace控制面板。F9截图
* 不要用于有反作弊的游戏，有的游戏即使单人默认也会运行
